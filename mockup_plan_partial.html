Partial-payment protocol (proposed)

RuleDetail
AccumulationAll txns matching the plan occurrence (same ±2 day window + name match, or explicit planRef link) sum toward the occurrence — same as prepay's pSum (v72.45)
Partial state0 < sum < 100% of plan amount → "Partly handled" row (warn border, yellow chip showing remainder)
Paid statesum ≥ 100% of plan amount → row removed (not rendered). No 50% threshold — full amount required
ChipPartial: yellow chip "₱X left" (tap → Add sheet prefilled with remainder + date + plan link). Paid: no row at all
Multiple entriesRow shows count: "₱5,500.00 logged (2 entries, last Sep 29)"
Explicit linkplanRef still wins — a linked txn counts regardless of amount (even 1 peso), same as today
Overflowsum > 100% (e.g. 120%) → still "Handled" (overpay is fine, no negative remainder shown)
Coach sub"On repeat" line shows the SUM of remainders (plan amount − logged) for all unpaid/partial plans in the cycle

Notes:
• Fully paid plans render NO row — the row simply disappears once accumulated ≥ 100% (cleaner than a "done" state).
• The 50% threshold is REMOVED — replaced by accumulation (any amount counts, 100% = done).
• The ±2 day window and name-match rules stay the same for fuzzy matching.
• The explicit planRef link (tap the chip on the Add form) still overrides everything — a linked 1-peso txn counts as that much toward the total.
• The chip on a partial row is tappable (opens Add sheet prefilled with the REMAINDER amount + due date + plan link), same UX as the "due" chip.
• "On repeat" in the sub-line now shows the live remaining total, not the gross plan total.
